# v0.5 Phase 1: role model configuration

AutoDev retains its Codex CLI provider and ChatGPT sign-in. This phase adds explicit settings to
the existing sequential, independent parallel and multi-stage workflows. It adds no dependencies,
API keys, provider, tools, autonomous delegation or permissions.

## Choices and evidence

| Preset ID | Architect / Planner | Every Developer | Reviewer |
| --- | --- | --- | --- |
| `fast` | `gpt-6.1-sol`, `medium` | `gpt-6.1-sol`, `low` | `gpt-6.1-sol`, `medium` |
| `balanced` | `gpt-6-astra`, `high` | `gpt-6.1-sol`, `high` | `gpt-6-astra`, `high` |
| `maximum_quality` | `gpt-6-astra`, `xhigh` | `gpt-6.1-sol`, `xhigh` | `gpt-6-astra`, `xhigh` |

The explicit-policy registry intentionally supports these two model IDs and the subset `low`,
`medium`, `high`, `xhigh`. Extra high is serialized as `xhigh`; `extra-high`, `max`, `ultra`,
arbitrary model IDs and execution options are rejected. Adding a model/effort requires a reviewed
registry change and tests, rather than accepting arbitrary Codex configuration through the UI.

The official [Codex models documentation](https://learn.chatgpt.com/docs/models) documents the
model IDs, but access still depends on sign-in, rollout and workspace settings. The
[configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) documents
`model_reasoning_effort`. These sources were checked on 2026-10-18. The installed native Codex
CLI's offline help/catalog inspection also supports these identifiers and efforts; it does **not**
establish this account's entitlement. AutoDev does not read the model cache, credentials or tokens
to assert access, and makes no automatic entitlement probe.

The [non-interactive transport](https://learn.chatgpt.com/docs/non-interactive-mode) returns final
JSON on stdout under `--output-schema`. AutoDev keeps this working transport. It does not switch
to JSONL/app-server events or treat model prose, CLI headers or configured defaults as proof of the
actual model. Reports explicitly store `observation_status: unavailable`, null observed model,
null observed reasoning and null observation source. The dashboard labels requested settings and
runtime observations separately, including failed calls. Historical reports say "Not recorded".
Successful calls establish that AutoDev received a valid response, not independently verified
runtime model identity. Service-side rerouting that the CLI does not report cannot be detected.

## Configuration and precedence

New dashboard forms start with Balanced and send it explicitly. Changing the preset clears form
overrides. Settings lists supported options with account access unverified. Per-role customization
is per run; this phase does not provide persistent browser-edited global presets.

For an explicit policy, precedence is: preset, typed operator role overrides, per-run role
overrides. Every resolved model and effort includes its source (`preset`, `operator`, `override`,
or `legacy`). Operator overrides are opt-in environment configuration:

```powershell
$env:AUTODEV_MODEL_PRESET = 'balanced'
$env:AUTODEV_ARCHITECT_MODEL = 'gpt-6-astra'
$env:AUTODEV_ARCHITECT_REASONING_EFFORT = 'high'
$env:AUTODEV_DEVELOPER_MODEL = 'gpt-6.1-sol'
$env:AUTODEV_DEVELOPER_REASONING_EFFORT = 'high'
$env:AUTODEV_REVIEWER_MODEL = 'gpt-6-astra'
$env:AUTODEV_REVIEWER_REASONING_EFFORT = 'high'
```

Setting a new Architect or reasoning variable also opts into a policy, with Balanced if no preset
is specified. Existing Developer/Reviewer model variables alone retain their legacy behavior.
Legacy arbitrary model names remain accepted through those old variables, without expanding the
explicit-policy registry. With an explicit preset, operator role values must pass the new registry.
An explicit dashboard/API selection replaces legacy flat model defaults; new typed operator role
overrides still apply. A CLI role flag overrides the corresponding operator setting.

The existing `run` command accepts `--model-preset fast|balanced|maximum_quality`, plus
`--architect-model`, `--developer-model`, `--reviewer-model` and corresponding
`--<role>-reasoning-effort`. Role flags without a preset use the configured policy or Balanced.
See README for Windows startup and commands. These commands make real Codex calls when executed;
the automated test commands do not.

The authenticated/CSRF-protected existing `POST /api/runs` accepts this optional field in addition
to the existing repository, instructions and workflow fields:

```json
{
  "model_policy": {
    "preset": "balanced",
    "overrides": {
      "reviewer": {"reasoning_effort": "xhigh"}
    }
  }
}
```

Omitting it retains operator configuration, which is legacy by default. Explicit `null` selects
legacy behavior and clears new operator overrides for that run. Resolved policies, executable
paths and Codex config strings cannot be supplied through this endpoint. New API policy input
never enters workflow-limit fields. Presets leave all concurrency, task/correction limits, call
budgets, approvals, Docker limits and deadlines unchanged. Slower reasoning can exhaust a deadline.

## Execution, errors and recovery

Each factory resolves one immutable policy before calling models. The same frozen snapshot routes
Architect/Planner, each isolated developer worker and Reviewer. Codex gets exact argv elements
`--model <id>` and `--config model_reasoning_effort="<effort>"`, without shell interpolation. In
legacy mode absent model/effort values produce no extra arguments. Existing forced ChatGPT login,
environment filtering, read-only sandbox, ignored user configuration/rules, disabled shell/search/
multi-agent tools, output schema, subprocess cleanup and limits are preserved.

| Error kind | Meaning and behavior |
| --- | --- |
| `configuration_invalid` | Typed policy validation or recognized CLI model/reasoning rejection; correct configuration. API input returns 422 before starting work. |
| `model_unavailable` | Model absent, unsupported or inaccessible to this account; explicitly choose a different configuration for a new run. |
| `authentication` | Codex reports login/authentication failure; repair login through Codex itself. AutoDev handles no credentials. |
| `rate_limit` | Codex usage/quota/rate limit; stop and retry later through an explicit new run. |
| `subprocess`, `timeout` | Installation, communication, process or deadline failure; stop, without provider fallback. |
| `response_parse`, `response_schema`, `response_invalid` | Invalid, oversized or schema-incompatible output; retain bounded sanitized diagnostics. |
| `implementation` | Invalid/incomplete owned-file output or ownership violation after a model call. Existing test/baseline/infrastructure classification remains separate. |

Unrecognized CLI failures remain generic subprocess failures; AutoDev does not guess entitlement
from arbitrary text. Recognized rejection/ignored-setting warnings are failures even with exit 0.
Raw stderr and authentication values are not persisted. Provider failures block queued developer
calls; already running peers remain bounded and finish, and their batch is not integrated.
There is no automatic provider retry, model/effort substitution or test-correction round for a
provider failure. Genuine generated-code validation failures retain the existing bounded repairs.

Reports have version 2 and include policy schema version 1 / preset revision 1, per-call IDs,
requested settings/provenance, lifecycle and error kinds. These are attached to agent attempts
using asyncio-local context, so concurrent calls cannot overwrite one another's metadata.

New checkpoint envelopes use version 2. Resume uses the saved resolved policy and limits rather
than resolving today's presets. Policy changes fail recovery validation. The loader verifies the
original canonical JSON checksum before typed defaults and again after loading; duplicate keys
and non-finite numbers are rejected. Version 1 checkpoints retain the old serialization/config
digest projection and all existing Git identity, commit, cleanliness, lock, timeout and budget
checks. Completed tasks are not repeated and original checkpoint files are not rewritten. Legacy
history loads without invented model observations. No unsafe-resume override is available.

## Automated verification and remaining limits

Deterministic tests cover preset resolution, partial overrides, immutability, legacy model handling,
invalid/unsupported inputs, exact safe argv, distinct CLI error kinds, ignored settings, output
validation, request-local observations, and model self-claims. Real Git integration with mocked
model responses covers overlapping developers, dependent inputs, milestone validation, provider
failures in all three roles, and frozen-policy recovery. Independently serialized v0.4 fixtures
cover original checksums, tampering and resume without repeating completed work. API tests cover
422 failures before work, legacy requests, persisted policy and separate limits. React tests cover
selection/overrides/evidence labels; browser tests cover both workflows and saved-policy resume.

Run the complete commands in README. No automated test needs ChatGPT, an API key or model network
access. The delivery report records actual results; mocks do not prove account access, live model
quality, CLI/server acceptance or Docker kernel enforcement. Exact CLI diagnostic wording may
change; unknown failures fail closed rather than selecting a substitute. Runtime observation
support, additional models/efforts, persistent custom presets and per-worker model variation remain
unsupported in this phase. The pre-existing optional API adapter remains legacy-only; policies
require Codex CLI and there is no fallback to paid APIs.
